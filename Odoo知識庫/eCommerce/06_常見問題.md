# Odoo Website & eCommerce 模組 - 常見問題（Q&A）

## 分類一：建站（Website Builder）

**Q1. 使用 Website Configurator 建站後，可以再修改配色、主題和頁面嗎？**

可以。Configurator 只是快速建站的起點，所有選項事後均可修改：
- 配色：Edit → Theme 分頁 → 修改 Primary/Secondary Color
- 字型：Edit → Theme 分頁 → 修改 Paragraph/Heading 字型
- 主題：在 Theme 分頁可重新選擇主題樣式
- 新增頁面：前台 → New → Page
- 不喜歡的內容直接刪除或重建即可

---

**Q2. 我沒有設計背景，如何讓網站配色看起來專業？**

Odoo 提供以下輔助工具：
1. 上傳 Logo → 系統自動從 Logo 提取品牌色系
2. 配色建議網站：colorhunt.co、Adobe Color Wheel（adobe.com/color）
3. 在 Theme 分頁的 Color Presets 中有多組預設配色方案可直接選用

---

**Q3. 如何加入 Google Fonts 清單中沒有的字型？**

1. 前往 fonts.google.com
2. 搜尋並選擇目標字型 → 點選後複製 Link 元素的完整 URL
3. 在 Odoo Website Builder → Edit → Theme → Fonts → 點選「Add a Google Font」
4. 貼上 URL → Save & Reload
5. 字型即出現在選擇清單中

---

**Q4. 我不小心點了「Discard」，剛才做的修改都不見了，怎麼辦？**

Discard（放棄）會撤銷自本次開啟編輯器以來所有未存的修改，無法復原。
預防措施：養成定期點選「Save」的習慣，每完成一個區塊就儲存一次。

---

**Q5. 如何讓某個區塊只在桌面顯示，不要在手機上顯示（或反之）？**

1. 在編輯模式下選取該區塊
2. 點選 Visibility 選項 → 設定為「Conditionally」
3. 點選桌面圖示（表示「此裝置不顯示」）或行動版圖示，依需求設定
4. 同一頁面可建立桌面/行動版各自專用的區塊，分別設定條件可見性

---

**Q6. Contact Form 可以同時送出 Email 和建立 CRM 機會嗎？**

不行。每個表單只能設定一個動作（Action）。若需要同時執行多個動作，有兩個解決方案：
1. 使用 Tabs 區塊建立多個分頁，每個分頁放一個獨立表單（各設定不同動作）
2. 在 CRM Opportunity 建立後，透過 Odoo 的自動化規則（Automated Actions）觸發 Email 發送

---

**Q7. 如何建立子選單（Drop-down Menu）？**

1. 前台 → Site → Menu Editor
2. 在選單清單中，將要成為子項目的選單項向右拖移縮排
3. 縮排後的項目即成為上方項目的下拉子選單
4. 可建立多層子選單

---

**Q8. 如何在頁面中建立錨點連結（點選後跳至同頁的特定位置）？**

1. 選取目標區塊（跳轉目的地的元素）
2. 點選「Create a link to target this section」→ 系統建立錨點
3. 到要放置連結的位置 → Insert/Edit Link → 輸入 `#錨點名稱`
4. 儲存後點選連結即可跳至目標位置

## 分類二：商品管理

**Q9. 商品批次匯入（Excel/CSV）失敗了，最常見的原因是什麼？**

常見失敗原因：
1. **欄位名稱不符**：Excel 欄位名稱必須與 Odoo 欄位名稱完全一致（建議先從 Odoo 下載範本）
2. **圖片檔名不符**：圖片欄填寫的檔名（如 `blue-plate.png`）必須與實際上傳的圖片檔名完全一致（含副檔名大小寫）
3. **格式問題**：價格欄不應含貨幣符號，日期欄需符合系統設定格式
4. **必填欄位缺漏**：Name（商品名稱）為必填欄位

建議：點選「Test」按鈕先驗證格式，待出現「Everything seems valid」再點選「Import」。

---

**Q10. 屬性的「Variant Creation」設定有三種（Instantly/Dynamically/Never），應如何選擇？**

| 設定 | 說明 | 適用情境 |
|------|------|---------|
| Instantly | 只要屬性與值加入商品，立即產生所有組合的變體 | 顏色、尺寸等實體規格（庫存需分開追蹤） |
| Dynamically | 變體在銷售訂單加入時才動態建立 | 客製化選項（如刻字服務） |
| Never | 不建立變體，屬性僅作為描述性欄位 | 純展示用資訊（如材質、產地），不影響庫存 |

**注意**：設定一旦用於商品後即不可修改，需在一開始就決定正確的類型。

---

**Q11. 商品變體的屬性「Extra Price」與在 Variants 頁面單獨設定價格有什麼差別？**

- **Attribute Extra Price**（在 eCommerce → Attributes 設定）：該屬性值的額外加價，套用至**所有**含此屬性的商品。例如：Size L 的 Extra Price 設 +€5，所有商品的 L 尺寸都會多 €5。
- **Variant 個別定價**（在 Variants 智慧按鈕中設定）：只針對**特定商品的特定變體**設定售價，不影響其他商品。

建議：若加價規則適用所有商品（如 L 碼一律加 €5），使用 Attribute Extra Price；若不同商品的相同屬性加價不同，使用 Variant 個別定價。

---

**Q12. 設定了缺貨訊息，但網站上還是沒有顯示，是什麼原因？**

需確認以下三個設定均已完成：
1. 商品 General Information 分頁 → 確認已啟用「Track Inventory」
2. 商品 eCommerce 分頁 → 確認已選擇「Show Out of Stock Message」（而非「Continue Selling」）
3. 確認該商品/變體的庫存數量確實為 0

---

**Q13. 「not in shop」功能的作用是什麼？與直接刪除分類有何不同？**

「Not in Shop」是分類的顯示設定，勾選後該分類（父分類）不會在商店頁面的分類導覽中顯示，但分類本身仍然存在，已關聯的商品也不受影響。

適用情境：例如「特賣」分類，準備促銷期間前先設為 not in shop，促銷開始時再取消勾選即可上線，無需每次重新建立分類或重新關聯商品。

注意：此設定僅適用於父分類，子分類無此選項。

## 分類三：電商設定

**Q14. 顧客可以在結帳時自行選擇價格表（如切換 EUR/GBP），但我不想讓一般顧客看到批發價格表，怎麼設定？**

在批發價格表的 eCommerce 分頁，將「Selectable」選項**關閉**。未設為 Selectable 的價格表不會出現在網站的價格表選擇器中。批發客戶的特殊價格需由後台人員手動指派給其 Portal 帳戶或客戶記錄。

---

**Q15. Promo Code（促銷代碼）和 Price List 有什麼關係？**

在 Odoo，促銷代碼是透過 Price List 實現的：
1. 建立一個 Price List（設定折扣規則）
2. 在該 Price List 的 eCommerce 分頁填入「E-Commerce Promotional Code」
3. 不勾選「Selectable」（避免顧客直接選到，只能透過代碼）

顧客在購物車輸入代碼後，Odoo 自動套用對應的 Price List 折扣。

---

**Q16. 如何讓特定商品分類的顧客只能「聯絡我們」而不能直接加入購物車？**

1. **Website → Configuration → Settings** → 搜尋「Hide add to cart」
2. 啟用此選項 → 選擇套用方式：「Specific Categories」
3. 在 Categories 欄位新增要隱藏加入購物車按鈕的分類
4. Save → 該分類的所有商品，加入購物車按鈕自動替換為「Contact Us」按鈕

---

**Q17. Click and Collect 的「Pay on Site」付款方式是如何產生的？需要手動設定嗎？**

不需要手動設定。啟用 Click and Collect 功能後，「Pay on Site」付款方式會**自動建立並發布**，顧客在結帳時選擇 Click & Collect 配送後即可看到此付款選項（代表顧客取貨時現場以現金或刷卡付款）。若需要修改此付款方式的設定，可在 Configuration → Payment Providers 中找到並編輯。

---

**Q18. 配送方式要「發布」才能讓顧客看到，忘記發布會有什麼影響？**

若配送方式未發布（Published 為 OFF），顧客在結帳的配送步驟中**不會看到此選項**。若所有配送方式都未發布，顧客將無法選擇配送方式，導致無法完成結帳。建議在測試完成後立即發布。

## 分類四：訂單與物流

**Q19. 電商訂單的三個階段（Quotation / Quotation Sent / Sales Order）分別代表什麼？後台應如何對應處理？**

| 階段 | 代表意義 | 後台建議動作 |
|------|---------|------------|
| Quotation（詢價單） | 商品已加入購物車，但顧客尚未完成結帳 | 若啟用棄單追蹤，系統會自動發送追蹤 Email；人工可聯繫顧客 |
| Quotation Sent（已傳送詢價單） | 顧客完成結帳流程，但選擇了需人工確認的付款方式（如銀行轉帳）| 確認收到款項後，手動確認訂單 → 變為 Sales Order |
| Sales Order（銷售訂單） | 付款已確認，訂單成立 | 安排出貨、確認發票（若未自動產生）、追蹤配送進度 |

---

**Q20. 棄單追蹤 Email 什麼情況下會自動發送？為什麼某些顧客收不到？**

棄單追蹤 Email 只能發送給以下兩類顧客：
1. **已登入帳號**的顧客（系統有其 Email）
2. 雖未登入，但**在結帳流程中填寫過 Email 地址**的訪客

以下情況無法發送：
- 完全匿名的訪客（只加入購物車但未進入結帳步驟）
- 未填寫 Email 就離開結帳的訪客

因此，建議在結帳流程的第一步要求顧客填寫 Email，以提高棄單追蹤的覆蓋率。

---

**Q21. 忠誠積點計劃可以同時在線上商店和實體門市（POS）共用嗎？**

可以。在建立忠誠計劃時，在「Available On」欄位同時勾選「Website」和「Point of Sale」，線上購物與門市消費即可累積同一個積點計劃的點數。顧客可在 My Account 頁面查看積點餘額。

注意：若要跨 POS 與 eCommerce 共用，需確認 POS App 已安裝，且兩個平台的積點名稱、兌換規則一致，避免顧客混淆。

---

**Q22. 我想修改某個頁面的 URL，但又不想失去 Google 的 SEO 排名，應該怎麼做？**

1. 先啟用開發者模式（Settings → Activate Developer Mode）
2. 複製現有頁面的舊 URL
3. **Website → Configuration → Redirections → New**
4. 建立 301（永久移動）重定向：從舊 URL → 新 URL
5. Save 後，再修改頁面 URL
6. 所有訪問舊 URL 的流量（含 Google 的 SEO 權重）都會轉移至新 URL

切勿直接修改 URL 而不建立重定向，否則舊連結會出現 404 錯誤，Google 的排名也會消失。

---

**Q23. 多語言網站中，如果我修改了英文版頁面，義大利文版的翻譯會自動更新嗎？**

不會自動更新。在 Odoo，各語言版本是獨立維護的：
- 修改主要語言（如英文）的內容後，其他語言版本的對應翻譯欄位**不會自動消失或更新**
- 系統不會自動重新翻譯已翻譯過的段落
- 如需更新，需切換至翻譯模式（Translate）重新翻譯修改過的段落

建議：重大內容修改後，檢查各語言版本是否需要同步更新翻譯。

**Q24. 同一個 Odoo 資料庫可以管理幾個網站？各網站的商品可以共用嗎？**

Odoo 支援在同一資料庫管理**多個**網站（數量無明確上限，取決於系統資源）。

商品共用方式：
- 後台建立的商品，預設在所有網站均可見
- 在商品表單的 Sales 分頁，可將「Website」欄位設定為特定網站（限制此商品只在該網站顯示）
- 若 Website 欄位留空 = 所有網站均顯示

各網站可擁有獨立的：網域、主題、頁面、選單、語言、Price List、Contact Form 動作。
