# CRM 模組｜內控點與風險

> 狀態：📖 知道（依據 CRM01–CRM22 影片整理，顧問應用視角）
> 主責：員工_03_流程內控助理（海瑟姆）
> 最後更新：2026-07-20
> 用途：顧問訪談時確認客戶的 CRM 內控設計是否到位

---

## 一、系統控制點

| 控制點 | 說明 | Odoo 預設行為 |
|-------|------|-------------|
| Probability = 100% 阻擋 | Lead 機率設為 100% 時，無法執行 Convert to Opportunity | ✅ 系統強制（100% = 已成交，不能再轉換）|
| Lost 商機自動隱藏 | Lost 的商機預設不顯示在 Pipeline | ✅ 系統預設（需手動 Filter → Lost 才能找到）|
| Lost Reason 紀錄 | 標記 Lost 時可填寫原因與 Closing Note | ⚠️ 非強制；客戶可跳過不填 |
| Mail Plugin 前置設定 | Gmail/Outlook 外掛需先在 Settings 啟用 Mail Plugin | ✅ 系統依賴（未啟用則外掛無法運作） |
| Developer Mode 前置 | Gamification 設定需啟用 Developer Mode | ✅ 系統強制（未開啟無法看到設定選項）|
| Leads 功能需啟用 | 若未啟用 Leads，系統只追蹤 Opportunity，無 Lead 清單 | ⚠️ 預設關閉；顧問需協助客戶決定是否啟用 |
| IAP 餘額控管 | Lead Mining / Enrichment / Partner Autocomplete / Visits to Leads 需 Credits | ⚠️ 額度耗盡時功能失效，無系統警告 |

## 二、權責控制點

| 控制點 | 說明 | 風險等級 | 備註 |
|-------|------|---------|------|
| Probability 可手動修改 | 業務人員可直接覆蓋 AI 計算的成交機率 | 中 | 手動改後不再自動更新；齒輪圖示可還原 |
| 商機指派無審核 | 業務可自行修改 Salesperson / Sales Team | 中 | 建議透過 Role-Based Access Control 限制 |
| Lost Reason 非必填 | 業務可標記 Lost 但不填原因 | 中 | 影響後續 AI 訓練品質與遺失原因分析 |
| 商機可任意還原 | 標記 Lost 的商機可一鍵 Restore，無審核 | 低-中 | 有意圖操縱數據的風險（重要客戶 Pipeline） |
| Activity 可指派給他人 | 活動的 Assigned To 可不同於商機 Salesperson | 低 | 跨人員協作正常需求，但需確認誰負責追蹤 |
| Multi-team 多重指派 | 啟用後業務人員可同時屬於多個團隊 | 低 | 需確認 KPI 是否會雙重計算 |

---

## 三、流程控制點

| 控制點 | 說明 | 風險 |
|-------|------|------|
| Rule-based Assignment 速度 | 每次只指派 1 Lead / 1 業務；頻率設太長 → 商機等待時間過久 | 建議 1–2 分鐘間隔 |
| Skip Auto Assignment | 個別業務可設定跳過自動指派 | 若主管不知情，部分業務可能永遠不接到分配商機 |
| Activity Plan 一鍵展開 | 套用計畫後一次產生多個活動；若計畫設計錯誤影響範圍大 | 建議先在 Demo 環境測試計畫設計 |
| Web 表單 Action 設定 | 表單 Action 若設為「Send Email」而非「Create Opportunity」，Lead 不會進 CRM | 確認 Website 表單 Action 設定 |
| Website Visitors 規則 | 訪客轉 Lead 依 IP 判斷公司身份；VPN 用戶可能誤判 | 需評估訪客資料品質；操作步驟見 02_操作SOP.md SOP-13d |

## 四、資料品質風險

| 風險 | 說明 | 建議對策 |
|------|------|---------|
| AI 成交率失準 | 歷史 Won/Lost 資料不足時，AI 預測不準確 | 初期導入後先手動積累一段時間的 Won/Lost 資料 |
| Lost 不填原因 | 業務怕被追責而跳過填寫 | 顧問建議客戶以管理政策（非系統）要求填寫 |
| Lead Enrichment 品質不穩 | IAP 資料品質依 Email Domain 品質而定；小公司/個人 Email 可能找不到 | 建議設為 On Demand（按需），而非 Automatic |
| Lead Mining 資料新鮮度 | Odoo 資料庫 30 萬筆資料的更新頻率不明 | 視為補充工具，非主要 Lead 來源 |
| UTM 未設定 | 沒有 UTM 則行銷歸因報表無資料 | 導入前需確認行銷部門是否配合設定 UTM |

---

## 五、跨模組內控注意事項

| 場景 | 說明 |
|------|------|
| CRM → Sales（商機轉報價） | Won 商機可直接轉報價單；確認誰有權限執行轉換 |
| CRM → Accounting（發票） | Invoicing Target 顯示的是已轉發票的金額，非所有 Won 商機金額 |
| CRM → Events（活動報名） | 需在 Events App 建立 Lead Generation Rule，並確認 Lead Type 欄位設定 |
| CRM → Website（訪客 Lead） | Visits to Leads 需 Credits；需確認客戶有購買 IAP 點數 |

## 六、顧問訪談確認清單

以下項目在顧問訪談時應向客戶確認：

**基礎設定**
- [ ] 客戶是否需要區分 Lead 和 Opportunity？（是否啟用 Leads 功能）
- [ ] 客戶是否有多個銷售團隊？各團隊負責的產品/地區/客群為何？
- [ ] 是否啟用 Multi-team（業務可屬於多個團隊）？

**商機管理**
- [ ] 商機 Pipeline 的階段名稱與定義是什麼？（需自訂）
- [ ] 業務員是否可自行修改成交機率？主管是否有審核機制？
- [ ] 商機遺失是否需強制填寫原因？哪些是主要原因？
- [ ] 是否需要業務主管定期 Review Pipeline？用什麼報表？

**活動管理**
- [ ] 目前業務跟進的標準步驟是什麼？（可能設計為 Activity Plan）
- [ ] 是否有自定義活動類型的需求（如：樣品寄送、實地量測）？

**自動指派**
- [ ] 商機是否需要自動分配？分配的規則是什麼（地區/產業/金額）？
- [ ] 是否有業務不應接受自動指派的情況？

**Lead 生成**
- [ ] 是否有官方網站？是否需要網站表單 Lead 生成？
- [ ] 是否有線上預約系統的需求？
- [ ] 是否有辦活動的需求（Events App）？
- [ ] 是否考慮使用 Lead Mining 主動開發？（需 IAP 費用）

**整合與費用**
- [ ] 業務人員主要用 Gmail 還是 Outlook？是否需要 Mailbox Plugin？
- [ ] 是否接受 IAP 付費功能（Mining / Enrichment / Autocomplete）？預算為何？
- [ ] 是否有行銷活動？是否使用 UTM 追蹤？

**遊戲化**
- [ ] 是否需要銷售競賽 / 目標挑戰機制（Gamification）？
- [ ] KPI 計量方式：數量（件數）/ 金額（營收）/ 進度（天數）？
