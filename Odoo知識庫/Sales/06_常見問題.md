## 發票與訂單

**Q：為什麼付款記錄在銷售訂單上，而不是發票上？**
A：因為銷售訂單是內部追蹤文件，發票才是用於稅務、費用追蹤與稽核的正式會計文件。需點 Create Invoice 才把付款帶進正式發票。（SAL01）

**Q：「Invoice what is ordered」和「Invoice what is delivered」差在哪？**
A：前者客戶依訂購數量付款（下單即可開票，適合現金流優先）；後者依實際交付數量付款（適合交付量不確定的易腐/散裝品）。（SAL01/02/14）

**Q：設定頁改了發票政策，既有產品會跟著改嗎？**
A：不會。設定頁只決定「新產品」的預設政策，既有產品不受影響，且可在個別產品表隨時更改。（SAL14）

**Q：服務型產品有哪些開票方式？**
A：預付/固定價、依交付數量、依里程碑（連 Project app）、依工時（連 Timesheets app）。（SAL03/14）

**Q：依交付開票時，服務產品怎麼記交付數量？**
A：實體品是 Validate 出貨；服務品則需在確認的銷售訂單上手動於 Delivered 欄輸入數量（用 options 選單開該欄）。（SAL14）

**Q：什麼是 Automatic Invoice？會自動寄給客戶嗎？**
A：線上付款確認後系統自動產生發票，但**不會自動寄送**（因已付款），可手動寄。（SAL14）

## 報價與範本

**Q：Quotation 和 Sales Order 差別？**
A：同一份單據的不同階段。報價經 Confirm（或客戶簽名付款）後轉為銷售訂單，啟動出貨/專案流程。（SAL04/07）

**Q：客戶在入口網站可以做什麼？**
A：可 Sign and Pay、給 Feedback、或 Reject（附原因）。拒絕訊息會記錄在 chatter，狀態轉 Cancelled。（SAL04）

**Q：Optional / Accessory / Alternative products 有何不同？**
A：Optional 為結帳時推薦的互補品；Accessory 為購物車結帳前顯示的加購品；Alternative 列於產品頁底部的替代品。（SAL08/03）

**Q：Quotation Builder 需要額外安裝什麼嗎？**
A：需要 Website app。若未安裝，啟用該設定時 Odoo 會自動安裝。（SAL13）

## 產品與變體

**Q：Attribute 和 Value 差在哪？**
A：Attribute 是屬性（如尺寸、顏色）；Value 是屬性的具體值（如 10、11、12 號）。變體是屬性與值的組合（如紅色 12 號）。（SAL09）

**Q：Variants Creation Mode 的 instantly / dynamically / never 差別？**
A：instantly=屬性值一加到產品就生成所有變體；dynamically=變體只在被加入銷售訂單時才生成；never=從不生成。**此模式一旦用於產品即不可更改**。（SAL09）

**Q：變體加價怎麼設？**
A：在屬性值的 Default Extra Price 欄輸入（如 fleece +$10），會加到原價並顯示於產品頁。（SAL09）

**Q：Track Inventory 一定要開嗎？**
A：需要追蹤數量才開（如椅子）；不需精確追蹤的（如辦公室的筆）可略過。開啟需安裝 Inventory app。（SAL08）

**Q：產品頁 Go to website 按鈕是紅色代表什麼？**
A：代表產品未發布，客戶看不到也買不到。點 toggle 切換 Published（綠色）即上架。（SAL08）

## 促銷

**Q：Coupon（優惠券）和 Promotional/Discount code（促銷碼）差在哪？**
A：優惠券發給特定客戶、通常一次性使用；促銷碼公開分享、可多次使用。（SAL16/17）

**Q：優惠券寄給指定客戶後，只有他能用嗎？**
A：不是。任何人只要有碼都能用，不需以特定客戶身分登入，客戶可轉贈。（SAL17）

**Q：忠誠點數有前提條件嗎？**
A：客戶必須有帳號才能集點（自行註冊或業務建為聯絡人）。登入後的合格購買或業務確認訂單會自動加入忠誠計畫。（SAL18）

**Q：怎麼做「最便宜品項免費」的促銷？**
A：Reward 選 discount → 設 100% → 套用範圍選 cheapest product。（SAL16）

**Q：Program Type 有哪些？**
A：Coupons、Next Order Coupons、Loyalty Cards、Promotions、Discount Code、Buy X Get Y、Gift Card。（SAL16）

## 稅務

**Q：稅要自己從頭設定嗎？**
A：通常不用。Odoo 建資料庫時依國別自動安裝 localization package，預設稅與 fiscal positions 已就緒。（SAL20）

**Q：Percentage of Price 和 Percentage of Price Tax Included 差在哪？**
A：前者稅外加（$100 × 15% = 稅 $15，總 $115）；後者含稅反推（簡易法：售價 ÷ (1 − 稅率)），同 15% 下稅額略高。（SAL20）

**Q：什麼是 Fiscal Position？**
A：財政狀況（國際稅則），用於跨國/跨區自動套用正確稅率，可設自動偵測（如 VAT Required + 國家）。（SAL21）

**Q：可以隨便新增稅或 Fiscal Position 嗎？**
A：不建議。應在會計團隊同意後才新建，否則會造成嚴重財務問題。（SAL21）

**Q：報價單上的稅怎麼決定？**
A：優先順序：產品自訂稅 > 聯絡人 fiscal position > 系統預設稅。可在明細 Taxes 欄手動更改。（SAL22）

## 運送與交付

**Q：運費可以怎麼算？**
A：固定價（Fixed price）或規則制（Based on rules，依 weight/volume/quantity）。規則制需在產品表先設對應數值，否則失效。（SAL23）

**Q：多條運費規則的套用順序重要嗎？**
A：非常重要。系統由上而下套用，第一條符合就套用。例如 100kg 規則需置於 30kg 之上。（SAL23）

**Q：Customer Lead Time 和 Security Lead Time 差在哪？**
A：Customer Lead Time 是告知客戶的交期（產品表設）；Security Lead Time 讓內部排程提前幾天（Inventory 設），作為延遲緩衝，客戶交期不變。（SAL24）

**Q：Dropshipping 訂單為什麼沒有出貨（Delivery）按鈕？**
A：因產品由供應商直送，系統產生的是 Purchase 智慧按鈕（採購單），需確認 PO 並 Validate 代發貨單才完成。（SAL25）

**Q：多個供應商時，代發貨用哪一個？**
A：清單第一個。請將指定代發貨供應商拖曳置頂。（SAL25）

## 價目表與佣金

**Q：怎麼讓價格都以 .99 結尾？**
A：用 Formula 運算，設 Rounding 到最近整數，Extra Fee 設 −0.01。（SAL26/27）

**Q：Discounts / Margins 設定頁的勾選只影響什麼？**
A：只決定折扣與毛利是否**顯示**在報價/銷售訂單上，即使不勾仍可在價目表使用。（SAL27）

**Q：Margins 規則怎麼保證獲利？**
A：based on Cost 並設 Margin 金額，系統確保售價至少高於成本該金額。（SAL27）

**Q：佣金 based on Achievements 和 Targets 差在哪？**
A：Achievements=依發票值固定百分比；Targets=依達成目標的百分比給佣，並可設 On-target Commission 與階梯 tiers。（SAL28）

**Q：佣金計畫核准後還能改嗎？**
A：可用 Reset to Draft 回草稿編輯或加業務。Approve 後才依 confirmed invoices 計算。（SAL28）

## 整合與匯入

**Q：Gelato Connector 需要哪些憑證？**
A：需從 Gelato 帳號取得 API Key 與 Webhook（含 signature header），貼入 Sales → Settings → Connector。（SAL29）

**Q：報價計算機一定要有報價範本嗎？**
A：是。沒有套用報價範本的訂單無法使用報價計算機。（SAL30）

**Q：匯入產品哪些欄位必填？**
A：標頭有星號的欄位（Name、Product Type）為必填，其餘為可增減的範例欄。（SAL31）

**Q：匯入時 First row as header 是什麼？**
A：預設開啟，讓 Odoo 用試算表第一列自動對應資料庫欄位；取消則需手動逐欄指派。（SAL31）

**Q：匯入變體時，基礎產品不存在會怎樣？**
A：Odoo 會自動建立基礎產品（即使未啟用變體功能），變體以 relations 關聯至基礎產品。（SAL31）
