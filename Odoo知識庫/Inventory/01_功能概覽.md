## 一、模組定位與業務場景

Odoo Inventory（庫存）是企業「管理實物商品從入庫到出庫」的核心應用，涵蓋從供應商收貨、倉庫儲位管理、揀貨出貨，到存貨調整、批次追蹤與物流標籤的完整倉儲循環。模組以家具公司 Stealthy Wood（及其姐妹公司 Stealthy Threads 時裝、Odoolicious 農場）為範例貫穿全課，展示各種業務情境下的設定方式。

### 核心倉儲循環

```
採購訂單確認（Purchase Order）
  → 建立收貨單（Receipt）
  → 驗收入庫（Validate）→ 更新在手庫存
  → 內部揀貨（Pick）
  → 出庫出貨（Delivery Order → Validate）
  → 更新庫存 / 生成出貨標籤
```

### 適用角色
- **倉庫經理（Warehouse Manager）**：設定規則、監控庫存、採購補貨、報表分析
- **倉庫操作員（Warehouse Operator）**：執行收貨、掃描條碼、移轉、揀貨
- **採購團隊**：觸發補貨規則、與 Purchase 模組協同
- **物流/出貨團隊**：建立批次、列印標籤、安排配送

## 二、各影片功能清單（INV01–INV37）

### Section 1：Inventory Basics（庫存基礎，INV01–INV09）

- **INV01 Inventory Basics: Receive and Store Stock**
  產品設定（Product Type = Goods、Track Inventory）、啟用 Storage Locations、收貨單操作（驗收數量、目標儲位）、Back Order 處理、Physical Inventory 頁面檢視與 Relocate 功能。

- **INV02 Inventory Basics & Outgoing Shipments**
  啟用 Barcode 與 Delivery Methods、兩步驟出貨設定（Pick then Deliver）、條碼掃描器揀貨流程、交付訂單驗收、FedEx 標籤自動產生。

- **INV03 Basic Warehouse Setup**
  一步、二步、三步收貨與出貨流程比較；選擇適合業務的複雜度；KISS 原則；啟用 Multi-Step Routes；在 Warehouse 設定 Inbound / Outbound 步驟。

- **INV04 Warehouses & Locations**
  Location vs Warehouse 定義、位置階層樹狀結構、Location Type（Internal、Customer、Transit、Production、Inventory Loss）、新增 Warehouse 需指定唯一地址。

- **INV05 Units of Measure**
  啟用 Units of Measure & Packagings、建立 UoM 類別與計算比率（含量 ÷ 參考單位）、廠商 UoM 與倉庫 UoM 自動換算、採購與庫存單位不同時的自動轉換。

- **INV06 Inventory Adjustments & Cycle Counts**
  盤點調整（Inventory Adjustment）vs 循環盤點（Cycle Count）概念；在 Location 設定 Inventory Frequency；Physical Inventory 頁面：Request a Count、Set Quantity on Hand、Set to Zero、Relocate、Apply All。

- **INV07 Integrate Landed Costs**
  落地成本定義（運費、稅款等額外成本）；需安裝 Accounting；產品類別設 AVCO 或 FIFO 成本法 + Perpetual 庫存評估；以 Service 類型產品代表落地成本；分攤方法（Equal / By Quantity / Current Cost / By Weight / By Volume）；在廠商帳單上建立 Landed Cost 並關聯收貨單。

- **INV08 Access Rights for Inventory Teams**
  倉庫經理（Admin 權限：Inventory、Purchase、Manufacturing）vs 倉庫操作員（User 權限：僅 Inventory）；無 Purchase/Manufacturing 存取的操作員僅能使用 Barcode App 進行收貨與移轉；職責分離降低誤操作風險。

- **INV09 Make-to-Order (MTO)**
  MTO（Replenish on Order）路線：僅在有實際需求（確認的 SO）時才觸發補貨；需搭配 Buy 或 Manufacture 路線告知補貨方式；啟用 Multi-Step Routes 及 Replenish to Order 設定；適用低頻、高客製化或高價值產品。

### Section 2：Replenishment（補貨，INV10–INV12）

- **INV10 Reordering Rules**
  補貨規則（最小 / 最大數量 / 數量倍數）；預測數量（Forecasted Qty）涵蓋已確認進出貨；手動觸發（Order 按鈕）vs 自動觸發（Scheduler，每日排程）；從 Replenishment Dashboard 或產品頁 Smart Button 存取。

- **INV11 Lead Times**
  四種前置時間：Customer Lead Time（產品 Inventory Tab）、Sales Security Lead Time（Inventory 設定）、Vendor Lead Time / Delivery Lead Time（廠商列表）、Purchase Security Lead Time（Inventory → Advanced Scheduling）；Days to Purchase（採購日數）；各時間相互獨立但共同決定最終排程。

- **INV12 Resupply Warehouse**
  多倉庫補貨：在目標倉庫（店面）的 Warehouse Configuration Tab 選擇補貨來源倉庫；在產品 Inventory Tab 勾選對應路線；搭配補貨規則自動觸發；補貨流程產生配送單（來源倉）+ 收貨單（目標倉）。

---

### Section 3：Traceability（追蹤性，INV13–INV15）

- **INV13 Lots & Serial Numbers**
  Lot（批號）適用大量相同產品批次；Serial Number（序號）適用個別追蹤；需 Goods 類型 + Track Inventory；接收時指派批號/序號（手動、匯入、Generate）；Traceability Smart Button 查看完整追蹤報告；Products → Lots/Serial Numbers 頁面。

- **INV14 Working with Perishable Products**
  易腐品管理：Lots 追蹤 + 到期日設定；Expiration Date / Best Before / Removal Date / Alert Date 四個日期欄位（均基於到期日計算）；設定 FEFO 移除策略於產品類別；Scrap Location（Inventory Loss 類型 + Loss Account）；報廢產品出現於損益表。

- **INV15 Expiration Dates**
  啟用 Lots & Serial Numbers → 才能看到 Expiration Dates 選項；在產品 Inventory Tab 設定各日期天數；接收時 Generate Lots（含批量）並可修改個別批次到期日；在 Lot/Serial Numbers 頁排序 Removal Date；在儲位設 FEFO 移除策略，揀貨時優先選最早到期批次。

---

### Section 4：Warehouse Transfers（倉庫移轉，INV16–INV21）

- **INV16 Push & Pull Rules**
  Routes（路線）由 Rules（規則）組成；Pull Rule：從客戶需求出發反向追蹤到補貨來源；Push Rule：產品到達某儲位時自動推送至下一位置；產品頁 Inventory Tab → View Diagram 圖形化顯示；Configuration → Routes 查看/編輯規則細節。

- **INV17 Putaway Rules**
  Putaway Rules 在產品到達父儲位時自動指定子儲位；設定依產品或產品類別；Store To 只能指定子位置（不能跨父位置）；支援 Sublocation 模式：No / Last Used / Closest Location（需搭配 Storage Category）。

- **INV18 Storage Categories**
  Storage Category 設定儲位容量上限（最大重量 + 依產品的數量上限）；啟用 Storage Locations 時自動啟用 Storage Categories；Putaway Rule 搭配 Closest Location 時選擇 Storage Category 以自動分配至未滿子儲位。

- **INV19 Cross-Docking**
  Cross-Dock 路線：產品從收貨碼頭直接移至出貨碼頭，不進倉庫；需 2 或 3 步驟入/出庫；產品設定 Buy + Cross-Dock 兩個路線；流程：SO → 自動產生 PO → 收貨 → Input Transfer → Output Transfer → 出貨至客戶。

- **INV20 Consignment**
  寄售庫存：廠商所有但存放於我方倉庫；建立 Receipt 時設定 Assigned Owner（廠商）；寄售品庫存報告顯示在手數量但庫存估值為 $0；需啟用 Configuration → Settings → Traceability → Consignment。

- **INV21 Dispatch Management System**
  DMS（派車管理）：結合 Fleet App 設定車輛類別（最大重量 / 體積）；Dock Location 勾選 Is a Dock Location；批次移轉選擇車輛後顯示重量/體積使用率；Map 按鈕顯示送貨地址地圖，支援 Google Maps 路線規劃。

### Section 5：Reserve Products（庫存保留，INV22–INV27）

- **INV22 Reservation Methods**
  三種保留方式：At Confirmation（確認 SO 即保留）、Manual（手動點 Check Availability）、Before Scheduled Date（提前 X 天自動保留，優先訂單可設較早天數）；在 Operation Types → Delivery Orders 設定。

- **INV23 Removal Strategies Overview**
  五種移除策略總覽：LIFO（最後入、最先出）、FIFO（最早入、最先出）、FEFO（最早到期、最先出）、Closest Location（最近儲位、最先出）、Least Packages（最少包裝數、最先出）；可設於 Location 或 Product Category。

- **INV24 FIFO & LIFO Removal Strategy**
  FIFO：適用有保存期限或容易過時的商品（食品、電子、時尚）；LIFO：適用不過期的重型商品（家具、建材）；需啟用 Lots & Serial Numbers + Storage Locations + Multi-Step Routes；設於 Location（Logistics Section）或 Product Category（Force Removal Strategy）。

- **INV25 FEFO Removal Strategy**
  First Expiry First Out：依 Removal Date 排序（到期日前 N 天）優先揀貨；需啟用 Lots & Expiration Dates；產品設定各日期天數；在 Product Category 設 Force Removal Strategy = FEFO。

- **INV26 Closest Location Removal Strategy**
  依儲位名稱字母數字順序決定「最近」；命名邏輯至關重要（Shelf 1 = 最近、Shelf 2 = 次近）；設於父儲位（Warehouse/Stock）的 Logistics → Removal Strategy；揀貨時優先選字母排序最前的有貨儲位。

- **INV27 Least Packages Removal Strategy**
  最小化開啟包裝數量；適用已包裝商品（小/中/大包裝）；需啟用 Packages；設於儲位 Logistics → Removal Strategy；揀貨時優先選容量最接近訂單數量的大包裝。

---

### Section 6：Packages and Packagings（包裝，INV28–INV33）

- **INV28 Packaging**
  Packaging（包裝規格）= 特定數量的產品組合（如：Fat Quarter = 0.25 yard、Bolt = 40 yards）；在 Configuration → Units & Packagings 建立；在產品 Sales Tab / Purchase Tab 指定；與 Units of Measure 共同管理；出貨單可顯示 Packaging 數量。

- **INV29 Packages**
  Package（包裹）= 任意組合的移轉容器（箱、棧板、推車）；啟用 Configuration → Settings → Packages；收貨或移轉時點 Put in Pack 自動建立；可在 Operation Types 設定 Move Entire Packages；Products → Packages 頁面查看倉庫中所有包裹。

- **INV30 Ship Multi-Box Packages**
  嵌套包裝（Pack in Pack）：將多個子包裹放入父包裹；適用多組件產品（Kit BOM）；在出貨單逐行設定 Destination Package 後再整體 Put in Pack；透過 Packages Smart Button 查看嵌套結構。

- **INV31 Multi-Package Shipments**
  單一出貨單分多包裝出貨（因產品分離協定或庫存不足）；透過 Details 連結逐行指定 Destination Package；部分不足時 Validate → Create Back Order；Back Order 日後補貨後再出貨。

- **INV32 Shipping Policy**
  出貨政策：Ship All Products at Once（等全部備齊再出）vs Ship Products as Soon as Available with Back Orders（可出的先出，其餘建立 Back Order）；在 Configuration → Settings → Operations → Picking Policy 設定。

- **INV33 Custom Returns Operation**
  自訂退貨作業類型（Operation Type = Receipt、序號前綴 = RE）；在 Delivery Orders 的 Returns Type 欄位選擇此作業類型；觸發後退貨單出現在對應 Card；可搭配 Quality Control Point（QCP）進行退貨品質檢查並設定失敗儲位。

---

### Section 7：Daily Operations（日常作業，INV34–INV37）

- **INV34 Batch Transfers**
  批次移轉（Batch Transfer）將多張揀貨單合併為一趟；啟用 Batch/Wave/Cluster Transfers；在 Operation Types → Delivery Orders 設定 Automatic Batches（可依 Carrier 分組）；Barcode App 執行批次揀貨；2 步驟流程：Pick（批次）→ Deliver（依 Carrier 自動分組批次）。

- **INV35 Cluster Picking**
  Cluster Picking：一位揀貨員同時為多張訂單揀貨，邊揀邊分裝至各訂單的專屬容器（Package）；需啟用 Packages + Batch Transfers；在 Detailed Operations 設定 Destination Package（可重複使用 Reusable Box）；完成後各訂單獨立包裝進行出貨。

- **INV36 Print Shipping Labels**
  啟用第三方物流連接器（FedEx、UPS 等）；設定 Shipping Method（Integration Level = Get Rate & Create Shipment）；設定公司地址、客戶地址、產品重量；在 SO 加入 Shipping Method 並 Get Rate；Validate 出貨單後標籤自動產生於 Chatter。

- **INV37 Wave Picking**
  Wave Picking：依倉庫區域分波次揀貨（一人一區）；需 3 步驟出貨（Pick → Pack → Deliver）；在揀貨明細頁依 Location 分組後建立波次（Add to Wave）；Operations → Wave Transfers 執行與追蹤；揀完後集中至 Packing Zone 再分單包裝。

## 五、與其他模組的連動關係

| 連動模組 | 連動點 |
|---------|------|
| **Purchase** | PO 確認 → 自動建立 Receipt；補貨規則觸發 RFQ；MTO 自動建立 RFQ |
| **Sales** | SO 確認 → 建立揀貨/出貨任務；2/3 步驟出貨 → Pick + Delivery；Smart Button 追蹤出貨狀態 |
| **Accounting** | Landed Costs 連動庫存評估與帳務日記帳；Perpetual 庫存評估自動產生分錄；Scrap 出現於損益表 |
| **Manufacturing** | MTO + Manufacture 路線自動觸發製令；Kit BOM 展開為多組件出貨；原物料消耗透過 Production Location |
| **Fleet** | Dispatch Management System 整合車輛類別與容量管理 |
| **Barcode** | Inventory 使用者自動取得 Barcode App 存取權；支援批次/叢集揀貨、收貨驗收 |
| **Quality** | 退貨作業可搭配 QCP 觸發品質檢查；3 步驟收貨可在 Input/Quality Control 各設檢查點 |
