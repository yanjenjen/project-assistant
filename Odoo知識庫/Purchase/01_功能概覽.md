## 一、模組定位與業務場景

Odoo Purchase（採購）是企業「取得原料/商品」的核心應用，負責從詢價到驗收的完整採購循環。模組以家具公司 Stealthy Wood 為範例貫穿全課：訂單爆增導致採購壓力提升，過去靠 Email、試算表與便利貼管理廠商的時代已過去，Purchase app 集中追蹤廠商、報價、訂單、收貨與帳單。

### 核心採購循環（RFQ → PO → 收貨 → 對帳）

```
Request for Quotation（詢價單 / RFQ）
  → 傳送廠商 → 廠商確認
  → Confirm Order（轉為 Purchase Order）
  → Receipt（收貨，連動 Inventory）
  → Create Bill（建立廠商帳單，連動 Accounting）
  → Register Payment（付款）
```

### 兩種帳單控制政策（Bill Control Policy）— 核心財務設定
- **依訂購數量開票（Ordered Quantities）**：確認 PO 後即可建立帳單，無需等待收貨。適合先付款取貨的情境。
- **依收貨數量開票（Received Quantities）**：只有在至少收到部分產品後才能建立帳單。搭配三方比對（3-Way Matching）確保僅支付已收到的品項。

## 二、各影片功能清單（PAL01–PAL10）

### Section 1：Buy and Receive（採購與收貨，PAL01–PAL05）

- **PAL01 Purchase Basics: Your First Request for Quotation**
  建立第一張 RFQ 的完整流程：選廠商 → 設定截止日 → 加入產品 → 觸發廠商價格表數量折扣 → Send RFQ（Email） → Confirm Order → 收貨 Validate → 更新庫存。示範即時新建產品（Create and Edit）。

- **PAL02 Purchase Lead Times**
  三種前置時間的定義、設定位置與計算邏輯：廠商前置時間（Vendor Lead Time）、採購安全前置時間（Purchase Security Lead Time）、詢價日數（Days to Purchase）。示範補貨報表（Replenishment）自動計算訂購時點。

- **PAL03 Reordering Rules**
  補貨規則設定（最小庫存 / 最大庫存 / 數量倍數），自動化採購流程。Odoo 每日自動跑排程器（cron）；手動觸發方式（單品 or 全品）。示範 Odoo 如何將銷售需求納入補貨數量計算（max qty + 未滿足銷售訂單）。

- **PAL04 Vendor Pricelists**
  廠商價格表設定：多廠商排序（第一順位為預設）、數量折扣（可設折扣百分比或折扣後金額）、交期設定。大量廠商匯入流程（Export 範本 → 填寫 → Import Records）。

- **PAL05 Approvals & Warnings**
  採購審核（Purchase Order Approval）：設定最低金額門檻，一般使用者需主管核准才可轉 PO。廠商警告（Warning / Blocking Message）：對廠商或產品設定提示或封鎖訊息，防止不當採購。

### Section 2：Manage Deals（管理合約，PAL06–PAL10）

- **PAL06 Blanket Orders**
  長期採購協議（框架訂單）：鎖定年度折扣但分批交貨。設定協議有效期、總數量與單價，分次建立 RFQ（各自指定交期與數量）。Smart button 追蹤所有子 RFQ/PO 狀態與累計金額。

- **PAL07 Bill Control（3-Way Matching）**
  帳單控制政策設定（系統全域 or 產品級別覆蓋）。「收貨數量開票」搭配三方比對（PO ↔ Receipt ↔ Bill）確保僅支付實際收到的品項。Other Information 分頁的 Billing Status 與 Should Be Paid 欄位說明。

- **PAL08 Purchase Agreements: Alternative RFQs - Calls for Tender**
  替代詢價（比價採購）：同時向多家廠商發送 RFQ，透過 Alternatives 分頁建立/連結替代報價，使用「Compare Products」頁比較廠商價格與交期（Odoo 自動標記最低價與最快交期），選定最佳廠商後確認訂單並取消其餘替代 RFQ。

- **PAL09 Purchase Agreement: Purchase Template**
  採購範本（固定採購清單）：適合頻繁重複採購相同產品組合。與 Blanket Order 差異：範本複製數量；框架訂單數量預設為 0。範本可設定或不設定廠商，追蹤歷史下單紀錄與累計金額。

- **PAL10 EDI Purchase to Sales Order**
  電子資料交換（EDI）：買方將確認的 PO 匯出為 XML 檔，賣方在自己的 Odoo Sales 應用上傳 XML，自動產生銷售訂單（客戶、產品、數量、價格均自動填入）。減少手動輸入錯誤，附上 XML 來源檔於 Chatter 確保可追溯。

## 五、與其他模組的連動關係

| 連動模組 | 連動點 |
|---------|------|
| **Inventory** | 確認 PO 產生收貨單（Receipt）；補貨規則從庫存觸發；收貨 Validate 後更新庫存 |
| **Accounting** | Create Bill 後進入帳務；Register Payment 完成付款對帳 |
| **Sales** | EDI：Purchase PO → XML → Sales Order；Dropshipping（見 Sales 模組）由 PO 觸發直送 |
| **Contact（Vendor）** | 廠商主檔（Internal Notes > Warning）、廠商分類 |

## 六、版本更正說明（2026-08-05）

「全局跑排程器」原寫「Inventory → Operations → Run Scheduler」，此路徑為 Odoo 舊版（17以前）介面，**Odoo 19 已移除此選單位置**。實測確認 v19 正確路徑：

1. 開啟 Developer Mode（開發者模式）
2. Settings（設定）→ Technical（技術）→ 自動化 → 安排的動作（Scheduled Actions）（⚠️「排程動作」為之前猜測翻譯之誤，2026-08-05已對照Jenny實際畫面更正為「安排的動作」）
3. 搜尋「補貨」找到「補貨：執行調度器（Procurement: Run Scheduler）」→ 點「手動執行」

此為 2026-08-05 於實際 v19-ce 沙盒環境驗證確認，取代原路徑，詳細操作SOP見 `02_操作SOP.md` PAL03。
