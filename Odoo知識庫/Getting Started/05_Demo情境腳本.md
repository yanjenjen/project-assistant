## Demo 情境｜Odoo 介面導覽（適合 Demo Day 開場）

**適用時機**：Demo Day 第一個 15 分鐘，客戶首次看到 Odoo 介面時

**目標**：讓客戶快速建立「Odoo 介面一致且直觀」的信心感

---

### 腳本流程

**1. 開場：主畫面 Home Dashboard（約 1 分鐘）**

說法建議：
> 「這是 Odoo 的主畫面，你們公司導入哪些模組，這裡就會出現哪些圖示。
> 今天先以 CRM 和 Sales 為例示範，後續可以根據你們的需求調整。」

操作：登入 → 指向主畫面的 App 圖示列

---

**2. 頂部工具列說明 Top Bar（約 2 分鐘）**

說法建議：
> 「右上角這排圖示是 Odoo 的快捷工具列，不管在哪個模組都看得到。
> 這裡有考勤打卡、訊息通知、待辦活動...」

操作：逐一點擊說明（考勤紅點 → Discuss → 活動時鐘 → 個人圖示）

**點亮客戶的亮點**：
- 所有圖示跨模組一致，不用重新學習
- 活動清單可以看到所有模組的待辦，不用一個個進去確認

---

**3. Smart Button 示範（約 2 分鐘）**

說法建議：
> 「Odoo 的一個強大之處是這個 Smart Button。
> 比方說，這張銷售訂單，頂部這個按鈕直接連到相關的出貨單、發票...
> 系統幫你把所有關聯資料串在一起，你不需要自己去找。」

操作：開啟一筆銷售訂單 Sales Order → 指向頂部 Smart Buttons → 點擊一個示範跳轉

**✨ 這個功能客戶反應通常最好**：直觀呈現系統整合的價值

---

**4. 麵包屑 Breadcrumbs（約 30 秒）**

說法建議：
> 「你隨時可以從左上角這裡知道自己在哪個頁面、怎麼過來的，
> 直接點麵包屑就可以回到任何一層。」

操作：點擊麵包屑示範返回

---

**5. 設定不自動儲存提醒（嵌入在 Demo 適當時機）**

說法建議：
> 「這裡要特別提醒一點：Odoo 所有的文件和記錄都是自動儲存的，
> 唯一的例外是設定頁面 Settings，這裡要記得手動點儲存。
> 這是最常見的新手誤解，記下來。」

---

### Demo 注意事項

- 開場導覽不要超過 10 分鐘，客戶耐心有限
- Smart Button 示範選擇有多個按鈕的頁面，視覺效果更好
- 多公司切換功能：若客戶沒有多公司需求，略過不提以免混淆

### 情境 A｜Chatter 整合溝通（任何業務場景均可嵌入）

**適用時機**：在示範任何模組時插入，展示 Odoo 溝通與協作整合

**腳本流程**：

開啟任一筆訂單或商機 → 右側 Chatter

說法建議：
> 「Odoo 很特別的一點是，每一筆記錄本身就是一個溝通頻道。
> 你在這裡可以直接傳訊息給客戶，也可以記錄內部備註讓同事知道進度。
> 所有操作歷程都自動記錄在這裡，不需要另外寫信或找聊天室。」

操作演示：
1. 點「發送訊息 Send Message」→ 輸入內容 → 看到收件人 → 傳送
2. 點「記錄備註 Log Note」→ 輸入 @ 同事名字 → 看到內部標示
3. 指向追蹤者 Followers 圖示 → 說明自動通知機制

✨ **亮點話術**：「這就是為什麼 Odoo 可以取代 Email + Line 群組 + 工作記錄本三個工具」

---

### 情境 B｜活動管理 Activities（業務 / 客服場景）

**適用時機**：Demo CRM 或 Sales 時，展示任務追蹤能力

**腳本流程**：

說法建議：
> 「如果你的業務需要追蹤很多客戶，系統可以幫你記住每個客戶下一步要做什麼。
> 圖示顏色代表緊急程度：橘色是今天到期，紅色是已逾期，不用一筆一筆去確認。」

操作演示：
1. 進入 CRM 管線 → 指向 Kanban 卡片上的活動圖示顏色
2. 點擊活動圖示 → 標記完成 Mark Done → 選「完成並安排下一步 Done & Schedule Next」
3. 切換到活動視圖 Activities View → 展示所有待辦的橫向總覽

✨ **亮點話術**：「業務主管可以在一個頁面看到所有業務的活動狀態，不用每個人回報」

---

### 情境 C｜資料匯入 Import（上線前資料移轉場景）

**適用時機**：談到「從舊系統移轉資料」時使用

**腳本流程**：

說法建議：
> 「Odoo 有內建的資料匯入功能，我們把舊系統匯出的 Excel 直接上傳就可以。
> 系統會自動比對欄位，你也可以手動調整。重點是有一個『測試 Test』按鈕，
> 讓你先確認格式對了再真的匯入，不會直接寫進去出錯。」

操作演示：
1. 進入 Contacts → 齒輪 → 匯入記錄 Import Records
2. 上傳範例 CSV → 系統顯示欄位對應
3. 點「測試 Test」→ 看到藍色成功訊息 → 說明這樣才是安全的做法

---

### 情境 D｜Group Access Rights 存取控制（IT / 管理層場景）

**適用時機**：談到「權限設計」時使用，目標對象為 IT 或管理者

**腳本流程**：

說法建議：
> 「Odoo 的權限設計是以群組為單位，不是針對個別員工。
> 好處是：新員工進來，把他加到對應群組，所有權限自動套用；
> 員工離職，從群組移除就好，不用擔心漏改哪個設定。」

操作演示：
1. Settings → Users & Companies → Groups
2. 開啟一個群組 → 指向四個頁籤：Users、Menus、Views、Access Rights
3. 點擊 Access Rights → 展示 CRUD 四種權限可精細控制每個模型

✨ **亮點話術**：「這就是為什麼人事異動時 Odoo 的維護成本低——群組設計好，日常維護只要改人員，不用改規則」

### 情境 E｜文件數位化行政流程（Documents + Sign）

**適用時機**：客戶提到「合約管理麻煩」、「廠商帳單處理耗時」、「想要無紙化」時

**腳本流程**：

說法建議：
> 「公司每天收到很多帳單和合約，Odoo 的文件 App 可以讓你把整個行政流程數位化。
> 供應商寄信到指定 Email，附件自動進系統；批次掃描的文件可以一頁一頁拆開，
> 直接轉成廠商帳單，AI 還會自動幫你填日期。」

操作演示：
1. 開啟 Documents App → 指向左側資料夾（Finance / HR / Internal）
2. 點開 Finance 資料夾 → Info & Tags → 展示 Email 別名欄位
3. 開啟多頁 PDF → 點「分割 PDF Split PDF」→ 拆分頁面 → 選「建立廠商帳單 Create Vendor Bill」
4. 進入帳單草稿 → 點「重新載入 AI 資料 Reload AI Data」→ 欄位自動填入
5. 開啟合約 PDF → 點「簽署 Sign」→ 拖入簽名欄位 → 傳送給客戶簽署

✨ **亮點話術**：「從掃描到入帳，整個過程不需要手動打一個字。」

---

### 情境 F｜服務型企業跨模組計費（Sales → Project → Timesheets → Invoice）

**適用時機**：顧問公司、工程公司、設計公司等以工時計費的服務業

**腳本流程**：

說法建議：
> 「如果貴公司是依工時計費的服務業，Odoo 可以讓整個流程自動串聯：
> 業務開一張報價單確認後，系統自動產生專案和任務；
> 工程師直接在任務上記工時，月底發票只要按一個按鈕就產生，
> 而且金額是從工時自動計算來的，不需要手動核對。」

操作演示：
1. Sales → 建立報價單 → 加入服務型產品（設定 Invoicing Policy = Timesheets）
2. 確認訂單 → Smart Button 出現「Projects」和「Tasks」
3. 進入任務 Tasks → Timesheets 頁籤 → 點「開始 Start」計時器 → 停止後 Log Time
4. 返回銷售訂單 → 看到「已交付 Delivered」數量自動更新（工時換算成天）
5. Sales → To Invoice → Orders to Invoice → 勾選訂單 → Create Invoices

✨ **亮點話術**：「業務、專案、工時、財務，四個部門的工作在同一個系統中無縫連接。」

---

### 情境 G｜製造業端對端流程（Website → CRM → Sales → MRP → Shipping）

**適用時機**：製造型企業，展示從接單到出貨的完整系統整合

**腳本流程**：

說法建議：
> 「這個情境示範從客戶在官網詢問到出貨的完整流程。
> 客戶填表格，系統自動建立 CRM 商機；
> 業務開報價單確認後，系統知道要生產哪個產品、用什麼料件；
> 生產完成後直接出貨、開發票，整個過程用一套系統追蹤。」

操作演示：
1. 網站聯絡表單 → 設定 Action = 建立商機 Create Opportunity
2. CRM App → 開啟剛產生的 Lead → 點「新建報價 New Quotation」
3. 加入產品（Drone / 製造商品） → 確認訂單
4. Inventory → 看到製造訂單 → 確認零件可用性 → 若缺料：Operations → Replenishments → 補貨
5. Manufacturing → Work Orders → 開始生產 → 完成 Produce All
6. 返回 Sales Order → Delivery → 列印標籤 Print Label → Validate
7. Create Invoice → 開立餘款發票 → 傳送客戶

✨ **亮點話術**：「同一筆訂單，業務、倉庫、工廠、財務同步看到進度，不用用 Line 群組通知。」

## 情境 H｜跨公司採購交易端對端示範（Multi-Company Transactions）

**適用場景**：集團型企業、有母子公司或加盟體系的客戶
**示範時長**：約 15-20 分鐘（含設定說明）
**前提**：已啟用 Sales / Purchase / Inventory / Accounting / Contacts；兩家公司已建立

**說法建議**：
> 「這個情境示範當集團內兩家公司互相採購時，Odoo 如何自動串接單據。
> 美國公司下一張採購單，加拿大公司的銷售訂單自動出現，省去人工重打。
> 每家公司的員工只看到自己公司的單據，財務也有獨立日記帳，合規追蹤完整。」

**操作演示**：
1. **設定說明**（買方公司）：Settings → Companies → Intercompany Transactions → 展示 Create Vendor Bills / Create Purchase Orders 開啟
2. **切換至買方公司** → Purchase 採購 → New → Vendor = 賣方公司 → 幣別自動切換 → 加產品 → Confirm Order 確認訂單
3. **切換至賣方公司** → Sales 銷售 → 移除「My Quotations」篩選 → 展示 OdooBot 自動建立的報價單（金額相符）→ Confirm 確認
4. **賣方出貨** → 點 Delivery 出貨智慧按鈕 → Validate 驗貨出貨
5. **賣方開票** → 回 Sales Order → Create Invoice → 選跨公司銷售日記帳 → Confirm
6. **切換回買方** → Accounting 會計 → 跨公司採購日記帳 → 展示自動出現的廠商帳單（草稿）→ Confirm

✨ **亮點話術**：
「一張採購單，兩邊的單據同步產生。財務稽核有 OdooBot 建立紀錄，知道是系統自動產生，不是人工輸入。每家公司各自獨立核帳，又可以由集團主管看到合併報表。」

**Demo 陷阱提醒**：
- 切換公司前確認目前在哪家公司（右上角醒目標示）
- 賣方 Sales 頁面記得移除「My Quotations」篩選，否則看不到 OdooBot 建的報價
- 不可從發票端開始（不會反向生成 PO）
