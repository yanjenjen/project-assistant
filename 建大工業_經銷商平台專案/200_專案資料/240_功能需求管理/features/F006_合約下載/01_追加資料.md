## 2026-07-13

**現況掃描**：`kenda_platform` module 內已有 `kenda.contract` model、`GET /contracts` API、陽春 Odoo 後台 list/form view，屬於早期照 PPT p10 搭的骨架，跟本份主需求對照有下列落差：
- `/contracts` 目前只用 `front_visible=True` 撈全部，完全沒有依國家＋胎種別篩選
- model 缺國家、胎種別欄位，無從比對
- 沒有下載單一檔案的 API（只有列表）
- `update_date` 只在 create 時預設，修改/補上傳不會自動刷新
- `store_level` 是自由 Char，非後台選單的三個固定值
- 「各廠商企只能維護自己廠」目前無任何欄位或權限規則支援

**已確認的技術決策（跟 Jenny 討論後拍板）**：
1. 後台維護（上載/刪除/下載/修改）走 **Odoo 原生後台**，不另外開發前台 portal 頁面／API，沿用現有 `base.group_user` 權限即可
2. 胎種別篩選 **沿用既有客戶分類欄位**（`kenda_dealer_category_rel` → `kenda_product_category`，代碼 BC/MC/AC/OTHER），不另建獨立胎種別欄位——48/49 筆經銷商已有值，覆蓋率足夠
3. 「各廠商企只能維護自己廠資料」的細權限**先不做**，第一版所有內部 Odoo 使用者共用同一後台權限，之後有實際跨廠誤改問題再補權限機制

**設計方向**：`kenda_contract.py` 新增 `country`（Char）＋`category_ids`（m2m → kenda.product.category）欄位供伺服器端比對用，不回傳到前台 JSON；`store_level` 改 Selection；`write()` override 使檔案異動時自動刷新 `update_date`；`content.py` 的 `GET /contracts` 改依 `authenticate()` 拿到的 dealer 的 country + category_ids 過濾，並新增 `GET /contracts/<id>/download` 路由。

## 2026-07-13（第七則，同日）— 前台店招申請表單國家欄位也修，順便處理了 F005-1 的快照問題

Jenny 用截圖回報兩個現象：① 前台「店招申請」表單自動帶入的國家欄位顯示裸代碼 `D16`；② Odoo 後台既有的店招申請記錄（`kenda.signage` #870）國家欄位顯示 `TW`（更舊的錯誤代碼），懷疑是不是被改壞了。

**釐清**：#870 是 2026-07-09（這次代碼體系修正之前）建立的舊資料，送出當下把當時經銷商的 `country` 值（那時候還是我第一版土砲的 `TW`）複製存進申請書——這是 F005-1 原本的設計（送出當下拷貝快照），不是這次改壞的。但 Jenny 確認「不要快照，要即時連動」，所以這次順便把這個行為改掉：

- **前台自動帶入（① 的修法）**：後端 `/auth/login`、`/auth/me`（`controllers/auth.py`）改成回傳已經組好「代號 說明」格式的字串（新增 `main.py` 的 `country_label()` helper，查 `kenda.code` code_type=CF），前端不用改任何程式碼，因為它本來就是直接把收到的字串原樣顯示。這次**沒有再動前端 bundle**。
- **後台既有記錄的即時連動（② 的修法，範圍擴大到 F005-1）**：`kenda_signage.py` 的 `country` 欄位從「送出當下寫死的 Char」改成 `compute='_compute_country', store=True`，依賴 `dealer_id.country`，之後經銷商主檔的國家異動，所有相關店招申請記錄會自動重算，不會卡在舊快照。同時發現既有的 `country_display` compute 只顯示說明文字（如「TAIWAN」），沒有代號前綴，跟其他地方「代號+說明」的格式不一致，一併補上代號前綴。`controllers/signage.py` 的 `create_signage()` 移除手動塞 `country` 的那行（現在完全交給 compute 自動處理）。
- 升級模組後，Odoo **不會自動幫既有記錄重算**新加上的 compute 欄位，額外在 shell 裡對全部既有 `kenda.signage` 記錄強制呼叫 `_compute_country()`／`_compute_country_display()` 並 flush，才讓 #870 這類舊記錄一次性補正——之後才會維持自動連動。

**驗收結果**：Jenny 重新整理 http://localhost:8071 的 #870 記錄，確認畫面顯示「D16 TAIWAN」，驗收通過。
