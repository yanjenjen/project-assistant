# 【F005-2】進度查詢（原「合約」分頁，已與原 F005-4 合併） — 主需求

- **功能編號**：F005-2
- **功能名稱**：進度查詢（原名「合約」，2026-07-16 與原 F005-4「進度查詢」合併，沿用「進度查詢」這個名稱）
- **父功能**：F005 店招申請（前端內部分頁，原 `value:"contract"`）
- **提出人／日期**：建大工業，內容來源 PPT + 2026-07-16 與 Jenny 討論確認
- **狀態**：已確認範圍（前台查詢），可開始開發

## 背景

原本 F005 底下規劃「合約」(F005-2) 與「進度查詢」(F005-4) 是兩個獨立分頁。盤點文件時發現兩者高度重疊：
- F005-2（原「合約」）明細畫面欄位（經銷商/國家/州省/車行/聯絡人/電話/廣告物縣市/施工項目/地址/處理進度/合約起訖日/距到期天數）**全部已存在於 `kenda.signage` model**（F005-1 開發時建立），資料來源就是 F005-1 申請書寫入的同一份申請記錄，不是另一張表。
- F005-4 明訂的查詢條件（車行名稱/廣告編號/經銷商/地址，模糊搜尋）與限制（只顯示「新增/維修/作廢移招」申請狀態）更完整明確。

2026-07-16 Jenny 拍板：**兩者合併成一個分頁，維持「進度查詢」這個名稱**。

## 關鍵欄位澄清（2026-07-16 與 Jenny 核對，見附圖 `kenda.signage,1` 後台畫面）

- **狀態**（`kenda.signage.state`：草稿／已送出／處理中／完成）＝後台表單右上角 stepper，**平台自己的流程狀態，現在就有在運作**。
- **申請進度**（`kenda.signage.apply_progress`）＝**要等建大 BPM 那邊做好才會串接**，目前欄位存在但多半是空值，不在本輪串接範圍內。
- 「狀態」與「申請進度」是兩個不同欄位，**分開顯示，不合併成一欄**。
- 目前已知未來要串接 BPM 的對應欄位就是「申請進度」，沒有其他欄位牽涉 BPM 串接。

## 前台

### 列表

| 欄位 | 來源 |
|---|---|
| 車行 | `tire_shop` |
| 狀態 | `state`（草稿/已送出/處理中/完成） |
| 申請進度 | `apply_progress`（目前多為空值，待 BPM 串接） |
| 合約起始日 | `contract_start_date` |
| 合約到期日 | `contract_end_date` |
| 申請項目 | `item_ids`（施工項目） |
| 更新日期 | `write_date`（Odoo 內建記錄最後修改時間） |

**查詢條件**（模糊搜尋）：車行名稱／廣告編號／經銷商／地址

**篩選**：只顯示 `apply_type` 為「新增／維修／作廢移招」的記錄（排除盤點/續約/資產作廢移轉等 BPM 內部業務類別，這些不開放前台查詢）

**分頁**：每頁 10 筆

### 明細（點列表某筆進去）

經銷商／經銷商名(不可改)／國家／州/省/地區／車行／聯絡人／電話／廣告物所在縣/市／施工項目(文字)／地址／狀態／申請進度／合約起始日／合約到期日／距到期天數

## 共用規則

- 只顯示**自己帳號**的資料，不可跨經銷商查詢
- 依**登入帳號國家**篩選，不可跨國查詢

## 資料來源

`kenda.signage` model（跟 F005-1 申請書是同一份申請記錄，欄位子集顯示，非獨立表）

## 本輪不做（待未來階段，不是懸而未決的問題）

- 「申請進度」跟 BPM 的即時串接：待建大 BPM 系統就緒後另開規劃
- 原 F005-4 主需求提到的「後台人員 Excel 三段式上下載維護」機制：這次不建，範圍縮小成純前台查詢
- 原 F005-4 Q2「前台備用欄位彈性開關」（後台打勾開放/改名）：待確認，不阻塞本輪完成度
