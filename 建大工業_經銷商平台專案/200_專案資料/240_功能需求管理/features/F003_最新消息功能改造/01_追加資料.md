## 2026-07-02

**調整位置**：後台

**新增需求**：控制每一則最新消息的「顯示對象」。

- 顯示對象種類：依資料來源分頁【客戶主檔】> B欄（購買產品類別 "productType"）分類
- 資料來源：`建大輪胎專案\0625文件\下單平台資料交換2026-06-25.xlsx`（注意：比 F001/F003/F004 先前引用的舊版更新，實查後確認舊版是 0612 而非 0608，見 [[03_資料來源變更]]）

**執行結果（2026-07-02，本機）**：已完成。`kenda.announcement` 新增 `target_category_ids` 多選「顯示對象」欄位（取代原本沒作用的單選 `product_category`），前台過濾邏輯已修正並驗證通過，客戶主檔已用 0625 版重新匯入（dealer 更新 46 筆）。細節見 `提示詞紀錄\2026-07-02_v2_顯示對象欄位.md`、`測試紀錄\2026-07-02_本機測試.md`。僅完成本機，未同步 aiuptop.com。

**設計調整（2026-07-02 同日）**：使用者反映白名單式「顯示對象」在分類數量變多時，若想「大部分人都要看、只排除1-2類」會需要手動勾選 N-2 個，操作太花時間。改成黑名單設計：欄位改名 `excluded_category_ids`（不顯示對象，留空＝全部顯示），語意反轉——選中的類別才是「排除」對象。過濾邏輯改成比對客戶類別是否落在消息的排除清單內，命中則隱藏。這次也修好一個過程中造成的迴歸：改欄位名稱時忘了同步改 `controllers/content.py`，一度導致前台 `/announcements` API 會噴錯（查詢不存在的欄位），已修正並驗證通過。前台不再回傳/顯示排除清單（原本顯示對象的客戶端標籤已移除，因為排除名單是內部控制邏輯，不適合顯示給看得到消息的客戶）。

## 2026-07-02（下午）

**調整位置**：前台

**新增需求**：最新消息列表新增排版切換。

- 使用者原話（14:52）：「前台的最新消息我需要，有2種排版方式，純文字條列(目前)、方形【圖+標題+部分文字】」
- 兩種排版：
  1. 純文字條列（目前既有的樣式，維持不變）
  2. 方形卡片：圖片＋標題＋部分文字（摘要）
- 切換方式：**客戶自己切換**（前台加切換按鈕，非後台統一設定）
- 適用範圍：**所有消息都套用卡片格式**（切到卡片模式時）；沒有圖片的消息，卡片不顯示圖片區塊，不可報錯（沿用 `00_主需求.md` 既有驗收標準）

**執行結果（2026-07-02，本機）**：已完成。前台列表頁右上角新增「列表／卡片」切換按鈕，選擇記在瀏覽器 `localStorage.kenda_news_view`，下次開啟沿用上次選擇。卡片模式為 grid 排版（圖片＋分類/公司別標籤＋標題＋內文摘要＋日期），沒有圖片的消息卡片自動略過圖片區塊。前台 JS bundle `index-BnEs5qT0.v10.js` → 複製為 `v11.js`（無原始碼可改，直接修補打包後的 bundle，用 `node --check` 驗證語法正確），`index.html` 改指向 v11。僅完成本機，未同步 aiuptop.com；瀏覽器實際點擊切換效果尚未做（只驗證到服務可連線＋新程式碼確實被送到瀏覽器層級）。
