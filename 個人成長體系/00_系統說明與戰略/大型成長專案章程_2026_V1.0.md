# 大型成長專案章程

- 專案名稱：個人成長作業系統（PGOS）
- 版本：2026 V1.0
- 狀態：試運轉
- 建置日期：2026-08-04
- 系統所有人：Jenny Lu
- 規劃期間：長期營運；每 12 週一個執行循環

## 目的

建立一套不依賴單一 AI 或平台、可由 Git 追蹤、可量化檢討、可累積專業資產的長期成長系統，使 ERP 顧問經驗逐步轉化為智慧流程顧問所需的思維、專業、技術、軟實力與市場能力。

## 暫定三年定位

成為能運用 AI、資料與流程方法，協助企業診斷 ERP 營運問題、設計改善方案並推動落地的智慧流程顧問。

此定位為待驗證假設，第一次正式季檢時應依個人意願、工作機會與實際證據校準。

## 成功標準

- 系統連續運作至少四個 12 週循環。
- 每季完成一個具有工作價值的成長型專案。
- 每季至少形成一項可重用方法、模板或 AI 工作流。
- 能力升級具有實戰證據，而非只有課程或自評。
- 重複性低價值工作時間下降，診斷、整合、協調及落地工作的比例提高。
- 所有公開或 Git 版本均不含客戶敏感資訊。

## 範圍

納入：職涯策略、能力架構、思維、軟實力、ERP／流程、資料／AI、顧問能力、執行狀態、專案、案例、作品、回饋、檢討與市場成果。

不納入：純粹為蒐藏而未連結使用情境的課程清單、未去識別化客戶原始資料、日常私人行程與醫療資料。

## 治理節奏

- 每週：確認成果、障礙、證據及下週唯一重點。
- 每月：檢查時間配置、案例沉澱與計畫偏差。
- 每季：正式能力盤點、證據審查、策略校準及下一個 12 週計畫。
- 每年：重新評估三年定位、年度成果與市場價值。

## 角色責任

- 本人：決策、執行、提供真實資料、確認自評與敏感資訊。
- AI 教練：提出問題、整理記錄、挑戰假設、協助產出及檢查一致性。
- 外部回饋者：主管、同事、客戶或導師，針對指定成果提供觀察，不代替本人決策。

## 主要風險

- 過度建置工具：遵守最小可行系統及管理時間上限。
- 自評失真：評分必須附證據及信心程度。
- 方向過多：每季只設定一項核心能力。
- 只有學習沒有應用：沒有六個月內使用場景者不列為主動項目。
- 機密外洩：所有案例與證據在提交 Git 前去識別化。
