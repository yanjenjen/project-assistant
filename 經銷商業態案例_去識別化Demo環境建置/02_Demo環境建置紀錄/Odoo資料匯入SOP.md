**⚠️ 匯入前必做：刪除技術名稱標題列**
這份資料集每個工作表都有「兩列標題」（第1列中文說明、第2列英文技術名稱如 customerNo）。Odoo「使用第一行作為標題」只會跳過第1列，第2列會被當成一筆真實資料匯入，產生一筆內容是「customerNo」「customerFullName」之類的假記錄。
**每次匯入新的工作表之前，先用這段 Python 刪除該工作表的第2列**，之後才上傳：
```python
import openpyxl
path = r'02_Demo環境建置紀錄\經銷商業態_去識別化Demo資料集.xlsx'
wb = openpyxl.load_workbook(path, data_only=True)
ws = wb['分頁名稱']   # 換成要匯入的分頁，例如 '集團產品主檔'
ws.delete_rows(2)
wb.save(path)
```
（客戶主檔已經處理過，之後不用重複做；但集團產品主檔、報價單頭/身、訂單單頭/身等分頁還沒處理，匯入前記得先做這步。）

**Odoo 匯入小知識（跑之前先知道）**：
- 每個模型（Contacts、Products、Sales Orders...）要分開匯入，不能把整個 Excel 檔案一次丟進去。
- 匯入畫面在該模型的列表頁 → 右上角齒輪／⋮選單 →「匯入記錄」（Import records）。
- 匯入時 Odoo 會要你把 Excel 欄位對應到系統欄位，這時就是回頭查 `接口清單_總檔_v2.xlsx` 的時候。
- 表頭+明細（例如報價單頭/報價單身）要用「外部 ID」（External ID）功能串起來，SOP 裡會標明哪個階段需要這個技巧，第一次遇到可以先跳過明細、只匯入表頭練手感。

**背景**：使用者提出這批產品未來會有「組合」概念——外胎（現有40筆產品）與內胎可以分開買，也可以搭售一組更划算的組合價。原始去識別化資料集完全沒有內胎這條產品線（核對「選項檔」的產品類別枚舉 B1/B2/M1/M2/I1/I2/A1/A2/EB/R1，全部都是外胎的應用分類），因此這是全新設計，不是既有資料的缺漏。

**Odoo 建模方式選型：BoM Kit（套件式物料清單）優於 Combo 組合商品**

| 方案 | 適用情境 | 是否適合本案例 |
|---|---|---|
| BoM（Bill of Materials）Kit / 幽靈型 BoM | B2B 經銷／零售場景，賣一組商品時，實際要各自扣減外胎與內胎的庫存，兩者都是有獨立庫存與售價的實體商品 | ✅ 採用——經銷商批發情境，外胎/內胎本身都要各自追蹤庫存與單獨銷售，套件只是「同時賣、給折扣」的包裝 |
| Odoo Combo 組合商品（product_combo，POS/電商常見） | 餐飲套餐/多選一型組合（如「主餐擇一+飲料擇一」固定總價），著重「顧客選項」而非庫存扣減 | ❌ 不適合——本案例是固定的一對一搭配（一條外胎配一條內胎），不是顧客多選一的套餐邏輯 |

**判斷原則**：如果組合裡的每個成分都要各自扣庫存、各自也能單獨銷售 → 用 BoM Kit；如果組合是「顧客從幾個選項中各選一個」的套餐邏輯（重點在選擇彈性、不一定要拆庫存）→ 用 Combo。本案例明確屬於前者。

**合成資料（seed=42，可重現）**：`內胎與組合商品_合成_v1.xlsx`（本資料夾），兩個分頁：

### 新任務：產品類別標籤 —— ✅ 已完成（2026-07-24）

**需求來源**：使用者發現「產品表也有類別」，要求仿照聯絡人標籤的做法，也幫產品建立類別標籤。

**資料依據**：原始資料集裡，`各公司報價產品主檔` 分頁有 `產品類別`（代碼，如B1/B2/M1/M2/I1/I2/A1/A2/EB/R1）+ `產品系列`（中文說明，如小輪徑/輪椅車/普通胎/旅行/環島/城市/公路車/登山車/雙效胎/熱熔胎/運動性能胎/高速胎）兩欄，用 `成品代號`(partNumber) 對應回 `集團產品主檔`/v2匯入檔的40筆產品，40筆全部對得上、無衝突。

**重要發現①：product.tag 沒有父層/子層結構**，跟聯絡人標籤（res.partner.category）不是同一種模型設計 —— product.tag 只有名稱/顏色/是否對客戶顯示，無法比照聯絡人標籤做「產品類別」父層+10個子層。已跟使用者確認，改用10個平行標籤，直接用中文名稱命名（小輪徑、輪椅車、普通胎、旅行/環島/城市、公路車、登山車、雙效胎、熱熔胎、運動性能胎、高速胎）。

**重要發現②：內部參考不能當比對鍵**。用「內部參考」欄位當匹配鍵時，Odoo會把每一列當成新記錄處理（因為內部參考不是Odoo內建的匹配欄位），導致「缺少必填的名稱欄位」錯誤。改用「外部ID」當比對鍵也不行——用匯出功能產生的 `__export__.product_template_XXX_hash` 這種暫時性外部ID來更新匯入時，會觸發 `product_product_combination_unique` 唯一鍵衝突（這批暫時外部ID沒有真正登記在 ir_model_data，Odoo處理時嘗試用該ID強制建立記錄，跟已存在的預設款式產生衝突，疑似此版本的匯入精靈bug）。網頁匯入精靈本身也**不提供**「資料庫ID(.id)」當手動比對欄位的選項（下拉選單搜尋不到，即使欄位標題精準寫成`.id`，精靈仍要求手動選欄位、選不到就當新記錄處理）。

**最終做法（改用 XML-RPC API 直接寫入，不透過網頁匯入精靈）**：
1. 匯出目前產品清單，用「我想更新資料（匯入相容匯出）」選項+「外部ID」欄位，取得 `__export__.product_template_{資料庫ID}_{hash}` 格式的字串，用正規表示式取出其中內嵌的資料庫ID（如 `__export__.product_template_167_d4889857` → 167）
2. 產品標籤10個先用一般匯入功能（名稱單欄）建立好，避免匯入時「建立缺少的值」選項不穩定的問題
3. 用 Python `xmlrpc.client` 連線 Odoo（`https://odoo-demo19.ideaxpress.biz/xmlrpc/2/{common,object}`），對每筆商品呼叫 `product.template.write([資料庫ID], {'product_tag_ids': [(6, 0, [標籤ID])]})`，40筆全數成功、無錯誤
4. 對應腳本：`scratchpad` 內的 `build_tags_with_dbid.py`（產生ID+標籤對照）、`assign_tags_xmlrpc.py`（執行寫入），未存到本資料夾（暫存檔）

**結果**：40筆商品全數正確掛上對應類別標籤（在商品表單「銷售」分頁的「標籤」欄位可見），已抽驗JA000007=雙效胎正確。

**給未來類似情境的教訓**：這個demo環境的Odoo 19版網頁匯入精靈，對product.template這種有「款式/變體」機制的模型，用ID類的比對鍵更新匯入不穩定（內部參考不支援、外部ID有bug）。**之後若同樣需要「用ID比對做批次更新」，優先考慮用XML-RPC/API直接寫入，比死磕網頁匯入精靈更快更穩**；純新增資料、或比對鍵是名稱/外部ID這種一般欄位時，網頁匯入精靈仍然好用（如這次的10個標籤本身、階段一~三的資料都是直接匯入成功的）。
