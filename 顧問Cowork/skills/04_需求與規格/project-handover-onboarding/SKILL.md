# 新專案接手與適應 Skill

## 角色分工

啟用本 Skill 後，依任務階段分配員工：

| 階段 | 主責員工 | 工作內容 |
|------|---------|---------|
| 資料盤點、接手七問、現況判斷 | 員工_01 砂砂 | 判斷資料完整度、回答接手七問、識別卡點與風險 |
| 建立/更新 JSON 與盤點表 | 員工_03 海瑟姆 | 維護專案接手狀態.json、文件有效性清單、範圍差異表 |
| 逐字稿轉會議紀錄、產出文件 | 員工_02 小果 | 逐字稿整理為 Word 草稿、產出專案摘要文件 |

## 啟動流程

### Step 0：判斷執行模式（強制，不可跳過）

觸發後，先判斷是哪種情況，再決定後續路徑：

```
判斷條件：
- 對話上下文或使用者說明中，是否已知企業代號與專案名稱？
  ├─ 是 → 直接進入 Step 1 搜尋任務包
  └─ 否 → 詢問企業代號與專案名稱後再進入 Step 1
```

詢問格式（僅在不知道時使用）：
```
了解，你正在接手一個新專案。
請先告訴我：
1. 這是哪個企業的專案？（企業代號或名稱）
2. 專案名稱或主題是什麼？
確認後我再開始協助盤點。
```

禁止在 Step 0 完成前：
- 推測或補寫使用者未明確提供的任何背景細節
- 建立任何資料夾或檔案
- 提供分析摘要或選項

### Step 1：搜尋現有任務包 → 判斷 Mode A 或 Mode B

搜尋 `顧問Cowork/91_跨員工協作區/` 與 `艾創點數位-ERP顧問/[企業代號]/` 是否已有此專案資料。

**→ Mode B：找到既有任務包或專案資料夾**

適用情境：專案已在 Cowork 建立，但使用者本人是新加入的。

執行順序：
1. 讀取既有任務包內的 `worklog.md`、`99_待確認事項` 或 `00_任務說明`
2. 讀取外層專案資料夾（210/220/230）中的現有文件清單
3. 依已有資料回答接手七問（Step 3）
4. 指出哪些題目有答案、哪些是缺口
5. 提出「人員接手摘要」，不重建整個任務包

不重複建立已存在的資料夾或 JSON，只補充缺少的部分。

**→ Mode A：找不到任何既有資料**

適用情境：全新專案，從零開始。

執行順序：接續 Step 2 → Step 3 → Step 4（建任務包）→ Step 5（建 JSON）

### Step 2：盤點收到的資料

列出本次收到的所有資料，逐份判斷：

| 判斷項目 | 說明 |
|---------|------|
| 資料類型 | 逐字稿 / 規格文件 / 進度表 / 信件 / 截圖 |
| 文件日期 | 建立或最後更新日期 |
| 版本 | v1 / v2 / Final / 修正版 |
| 確認狀態 | 草稿 / 內部確認 / 客戶確認 / 待確認 |
| 有效性 | 目前有效 / 可能過期 / 已被取代 / 無法判斷 |
| 資料缺口 | 缺頁 / 缺附件 / 缺背景說明 |

### Step 3：回答接手七問

依現有資料盡力回答，無法回答的標示「待確認」：

1. 這個專案最初要解決什麼問題？
2. 正式範圍與交付物是什麼？
3. 目前處於哪一個專案階段？
4. 已經完成並確認的是什麼？
5. 過去發生過哪些重大變更？
6. 現在主要卡點與風險是什麼？
7. 接下來一至兩週最重要的事情是什麼？

### Step 4：建議任務包結構

提出建議，等使用者確認後建立：

```
顧問Cowork/91_跨員工協作區/
└─ [企業代號]_[日期]_[專案名稱]/
   ├─ 00_專案接手總覽/
   │  ├─ 專案一頁式摘要.md
   │  ├─ 專案接手狀態.json
   │  └─ 資料缺口與待確認.md
   ├─ 01_原始資料/
   │  ├─ 逐字稿/
   │  └─ 客戶文件/
   └─ 02_會議紀錄/
      └─ Word正式會議紀錄/
```

> 初版只建 00、01、02，資料量少時不建空殼。

### Step 5：建立或更新 `專案接手狀態.json`

每次收到新資料後更新此 JSON。
JSON 模板參見：`00_共用規則與知識庫/02_共用模板/新專案接手與適應工作流_參考規則.md`

### Step 6：逐字稿轉正式會議紀錄（若有逐字稿）

交由員工_02 小果執行，依以下流程：

```
逐字稿
→ 清理口語與重複內容
→ 辨識議題與發言角色
→ 區分討論與確認決議
→ 整理待辦與待確認
→ 標記負責人與期限
→ 對照現有專案狀態
→ 產出 Word 會議紀錄草稿（放入 02_會議紀錄/）
```

不得補寫未提及的負責人、未確認的期限、未確認的開發承諾。

## 每次回覆格式

### Mode B 回覆格式（人新到既有專案）

**1. 現有資料清單**
列出讀到的既有文件（worklog、任務包、外層專案資料夾內容）。

**2. 接手七問現況**
逐題回答，有答案的標來源，沒答案的標「待確認」。

**3. 你目前掌握的 vs 尚未掌握的**
用兩欄清楚對比，讓使用者一眼知道缺口在哪。

**4. 建議下一步**（不超過 5 項，依優先順序）

**5. 等待確認**
未經使用者確認，不新增或修改任何檔案。

---

### Mode A 回覆格式（新專案從零開始）

**1. 本次收到資料**
列出資料清單與類型。

**2. 資料完整度判斷**
說明目前能回答幾題接手七問，缺口在哪裡。

**3. 已確認事項**
有明確依據的內容。

**4. 待確認事項**
缺資料、矛盾或無法判斷的內容。

**5. 建議閱讀順序**
若資料量多，指出應優先閱讀哪幾份。

**6. 建議任務包結構**
提出後等使用者確認，不主動建立。

**7. 建議下一步**（不超過 5 項）

**8. 等待確認**
未經使用者確認，不建立、搬移或修改任何檔案。

## 執行原則

- 不以單一文件推斷專案全貌，必須交叉比對
- 不要求先讀完所有資料，依優先順序閱讀
- 所有推論必須標示「推論」，不寫入正式文件
- 資料矛盾時列出差異，不自行選擇其中一版
- 每次更新 JSON 後，在 `worklog.md` 留一筆紀錄
