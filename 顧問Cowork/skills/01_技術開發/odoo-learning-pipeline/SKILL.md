# odoo-learning-pipeline｜Odoo 逐字稿學習處理 SOP

> 版本：v0.1.0｜狀態：試行中
> 主責：員工_03_流程內控助理（海瑟姆）主執行；員工_02_文件資料助理（小果）負責 Notion 與文件輸出
> 建立日期：2026-07-10

---

## 一、Skill 定位

將一份 Odoo 教學影片逐字稿，轉化為：
- **Track B（Notion）**：個人學習版 SOP，操作細節 + 時間錨點 + 對照表
- **Track A（內部知識庫）**：顧問應用版，內控點 + 業務場景 + Demo 腳本 + Obsidian 連結
- **學習機制更新**：深度狀態追蹤 + 品質回饋 + 版本標示

---

## 二、觸發條件

**主要觸發詞**（推薦使用）：
- `逐字稿：` + 逐字稿內容（直接貼上）
- `odoo-pipeline：` + 逐字稿內容
- `幫我處理這份逐字稿`

**輔助觸發詞**（語境明確時啟用）：
- `幫我整理這支影片`
- `這是 Odoo [模組名稱] 的逐字稿`

---

## 三、執行前確認

啟動前，先詢問使用者以下資訊（若逐字稿中已有則自動帶入）：

| 項目 | 說明 |
|------|------|
| 模組名稱 | 例：CRM / Sales / Purchase / Inventory / Accounting / Manufacturing |
| 影片來源 URL | YouTube 網址或描述 |
| Odoo 版本 | 例：Odoo 19（若不確定請標示「待確認」） |
| 逐字稿語言 | 中文 / 英文 / 中英混合 |

## 四、7 步驟標準流程

### ▌ Step 1｜確認逐字稿

**目的**：確保輸入素材完整、模組定位正確，避免後續分析方向錯誤。

執行項目：
1. 確認模組名稱、影片來源、Odoo 版本
2. 確認逐字稿是否完整（有無明顯截斷或遺漏）
3. 識別這支影片的**核心主題**（例：「這支影片講的是採購審批，不是完整採購流程」）
4. 預估將產生幾個 SOP 段落

輸出格式：
```
【逐字稿確認摘要】
模組：[模組名稱]
影片來源：[URL]
Odoo 版本：[版本 / 待確認]
核心主題：[一句話說明這支影片的主題]
完整性：完整 / 部分截斷（說明）
預估 SOP 數量：[N 個操作段落]
```

⚠️ 若逐字稿明顯不完整，先提示使用者補充，不繼續執行後續步驟。

---

### ▌ Step 2｜分析內容

**目的**：從逐字稿萃取結構，判斷操作流程、欄位、業務邏輯與顧問應用點。

執行項目：
1. **操作流程識別**：找出每個獨立操作段落（時間錨點、操作路徑、步驟）
2. **欄位與單據識別**：列出出現的欄位名稱、按鈕、單據類型
3. **業務邏輯識別**：系統背後的規則、觸發條件、狀態流轉
4. **版本特徵識別**：若有畫面截圖描述或特定功能名稱，推測 Odoo 版本
5. **顧問應用點預判**：哪些地方對客戶導入有意義、哪些有風險

輸出格式：
```
【內容分析摘要】
操作段落：
  SOP-01：[段落名稱] → [主要步驟概述]
  SOP-02：...

出現的欄位/單據：[清單]
核心業務邏輯：[說明]
顧問應用預判：[哪些是高價值顧問知識點]
版本標記：Odoo [版本] / 待確認
```

等待使用者確認分析方向後，再進行 Step 3。

---

### ▌ Step 3｜確認是否更新 Notion

**目的**：確認 Track B 的寫入策略，避免重複或錯誤覆蓋。

執行項目：
1. 搜尋 Notion 知識庫，確認此功能是否已有舊版頁面
2. 提出以下選項供使用者確認：

| 情境 | 建議 |
|------|------|
| Notion 無此功能頁面 | 建立新頁面 |
| Notion 已有舊版，內容相同 | 跳過，不重複建立 |
| Notion 已有舊版，內容不同 | 詢問：更新舊頁面 / 建立新版頁面 |
| Notion 已有但版本不同 | 建立新頁面，標示版本差異 |

3. 確認 Notion database 欄位值：

| database 欄位 | 建議值 |
|-------------|-------|
| 系統類型 | Odoo |
| APP模組 | CRM / Sales / 採購 / （新模組需新增選項）|
| 知識類型 | SOP / 名詞解釋 / 路徑（可多選）|
| 副類型 | 視內容決定 |
| 版本日期 | 學習日期 |
| 網址 | YouTube URL |

⚠️ Inventory、Accounting、Manufacturing 目前 Notion 的 APP模組 選項尚未建立，需先新增選項再寫入。

等待使用者確認後，由員工_02（小果）負責寫入 Notion。

Notion 寫入格式規範：
- 每個 SOP 段落用 `##` 標題
- 時間錨點格式：`時間：MM:SS - MM:SS`
- 操作路徑格式：`[模組] → [子選單] → [功能]`
- 英中對照格式：`中文名稱 [英文名稱]`（中文在前，英文方括號補充）
- 每頁末附「關鍵欄位對照表」
- 每頁末附「這支影片真正要學會的觀念」

---

### ▌ Step 4｜萃取顧問知識

**目的**：從學習者視角（Notion）提升為顧問應用視角，這是 Track A 與 Track B 最大的差異。

執行項目：

**4-1 內控點萃取**（寫入 04_內控點與風險.md）

| 類型 | 說明 | 範例 |
|------|------|------|
| 權責控制 | 誰能執行、誰需核准 | 採購超過門檻需主管核准 |
| 系統控制 | Odoo 自動執行或攔截 | Blocking Message 阻擋特定產品 |
| 單據控制 | 透過單據流轉確保合規 | RFQ → To Approve → PO |
| 例外控制 | 針對異常情境的處理規則 | 緊急採購繞過審批的補救程序 |

**4-2 顧問訪談問題萃取**（寫入 04_內控點與風險.md）

格式：
```
□ 客戶是否有 [情境]？
□ 貴公司的 [流程] 是如何處理的？
□ [功能] 的授權層級是如何設計的？
```

**4-3 業務場景對應**（寫入 01_功能概覽.md）

說明這個功能在哪種業務場景下會被啟用：
```
適用情境：
- 新進員工採購權限控管
- 多層級審批需求
- 特定供應商管理

不適用情境：
- 小型公司只有 1 位採購人員
```

**4-4 Demo 腳本要點**（寫入 05_Demo情境腳本.md）

從逐字稿中提取影片本身的 Demo 流程，整理為顧問展示可用的腳本。

**4-5 常見問題萃取**（寫入 06_常見問題.md）

從影片中「初學者容易搞混的地方」提取，整理為 FAQ 格式。

## 六、不適用情境

以下情境**不應觸發此 Skill**：

- 使用者提問「Odoo 這個功能怎麼用」→ 直接回答，不啟動完整流程
- 使用者上傳 Odoo 畫面截圖 → 使用 `odoo-ui-analyzer` Skill
- 使用者要建立功能說明書 → 使用 `odoo-module-spec-writer` Skill
- 使用者提供的不是逐字稿而是摘要筆記 → 確認是否仍要執行（萃取深度會受限）

---

## 七、執行節奏

**不要一次全部完成再輸出**。應依以下節奏執行：

1. Step 1 完成 → 輸出確認摘要，**等待使用者確認**
2. Step 2 完成 → 輸出分析摘要，**等待使用者確認**
3. Step 3 完成 → 提出 Notion 寫入建議，**等待使用者確認**
4. Step 3 確認後 → 由小果寫入 Notion
5. Step 4-5 完成 → 輸出 Track A 更新清單，**等待使用者確認**
6. Step 5 確認後 → 執行 Track A 寫檔
7. Step 6-7 → 執行 Obsidian 更新 + 輸出品質回饋

**核心原則**：每個有寫檔動作的步驟，都需要使用者確認後才執行。

## 八、寫檔限制

- 不自動寫入，每次寫檔前需使用者確認
- Notion 頁面建立由員工_02（小果）執行，不由海瑟姆直接操作
- Track A 更新採 Append 方式，不覆蓋既有已確認內容
- 版本差異更新前，需標示「建議修改原因」，使用者確認後才執行
