## 一、文件目的

本文件提供「中途接手專案」的完整執行參考，包含：
- 接手七問內容定義
- 五類必要產出物格式
- 專案接手狀態 JSON 模板
- 文件閱讀優先順序規則
- 現況四分類定義

Cowork 執行 project-handover-onboarding Skill 時，應參照本文件產出對應格式。

---

## 二、接手七問定義

| 題號 | 問題 | 說明 |
|------|------|------|
| Q1 | 這個專案最初要解決什麼問題？ | 業務背景、痛點、導入動機 |
| Q2 | 正式範圍與交付物是什麼？ | 合約範圍、本次要做什麼、不做什麼 |
| Q3 | 目前處於哪一個專案階段？ | 規劃 / 設計 / 開發 / 測試 / 上線 / 維運 |
| Q4 | 已經完成並確認的是什麼？ | 需客戶或雙方正式確認，非「討論過」 |
| Q5 | 過去發生過哪些重大變更？ | 需求異動、範圍調整、決議推翻 |
| Q6 | 現在主要卡點與風險是什麼？ | 缺資料、責任不清、時程壓力、範圍膨脹 |
| Q7 | 接下來一至兩週最重要的事情是什麼？ | 具體行動、負責人、期限 |

七題全部回答 → 第一階段接手完成。
有題目無法回答 → 標示「待確認」並說明缺少哪些資料。

## 三、文件閱讀優先順序

### 第一優先（先讀這五份）
1. 合約、報價單或正式範圍文件
2. 最新需求或規格文件
3. 最新進度表
4. 最近 2 至 3 次會議紀錄
5. 現行待辦、問題或缺口清單

### 第二優先
- 重大需求第一次被提出的會議
- 有明確需求變更的會議
- 有客戶或我方承諾的會議
- 有高階主管參與的會議

### 第三優先（最後再看）
- 純進度回報
- 已被新版文件取代的舊版本
- 沒有決議的重複討論

## 四、現況四分類

| 分類 | 定義 |
|------|------|
| 已完成 | 已開發 / 已確認 / 已交付 / 已驗收，有正式依據 |
| 進行中 | 目前有人在處理，有明確負責人與進度 |
| 待確認 | 已提出但尚未取得明確決議 |
| 風險／卡點 | 缺資料 / 需求矛盾 / 責任不清 / 範圍膨脹 / 時程不足 |

## 五、必要產出物格式

### 5.1 專案一頁式摘要

```
專案名稱：
企業名稱：
企業代號：
專案目的：
正式範圍（含）：
非本次範圍（不含）：
目前階段：
已完成：
進行中：
待確認：
主要卡點：
近期里程碑：
下一步：
資料完整度：（接手七問已回答 X/7 題）
最後更新：
```

---

### 5.2 文件有效性清單

| 文件名稱 | 日期 | 版本 | 用途 | 確認狀態 | 是否最新 | 取代關係 | 備註 |
|---------|------|------|------|---------|---------|---------|------|

危險訊號（出現以下情況須標記）：
- 檔名看不出版本
- 文件內沒有日期
- 會議已改過但規格書沒更新
- 多份文件同時存在，無法判斷哪份有效
- Final 後面又出現 Final2 / 最新版 / 最新版修正

---

### 5.3 專案時間線

| 日期 | 事件 | 討論或決議 | 後續變更 | 目前狀態 | 來源 |
|------|------|----------|---------|---------|------|

只記錄重大事件：
- 專案啟動 / 範圍確認 / 需求變更 / 規格確認
- 開發完成 / 測試開始 / 重大問題 / 驗收
- 里程碑延遲 / 客戶或我方重大承諾

---

### 5.4 範圍、現況、差異盤點

| 功能或議題 | 原始範圍 | 後續討論 | 目前現況 | 差異 | 是否需變更評估 | 狀態 |
|----------|---------|---------|---------|------|-------------|------|

用途：辨識原範圍與現況不一致、需求擴增、文件未同步、超出範圍情況。

---

### 5.5 待辦與待確認清單

| 編號 | 項目 | 類型 | 來源 | 下一步 | 負責人 | 期限 | 狀態 | 卡點 |
|------|------|------|------|-------|-------|------|------|------|

類型選項：待辦 / 待確認 / 待補資料 / 待評估 / 待客戶確認 / 待內部確認

## 七、會議紀錄標準結構

逐字稿整理為 Word 草稿時，應依以下結構產出：

```
1. 會議基本資料（日期、地點、出席者）
2. 會議目的
3. 討論議題
4. 客戶提出事項
5. 我方回覆
6. 會議決議（已確認）
7. 待確認事項
8. 待補資料
9. 待辦事項
10. 負責人與期限
11. 範圍與風險備註
```

不得補寫：未提及的負責人、未確認的期限、未確認的開發承諾、未確認的系統規則。

## 八、完成標準

以下十項均可清楚回答，視為第一階段接手完成：

- [ ] 知道專案為什麼做
- [ ] 知道正式範圍
- [ ] 知道目前階段
- [ ] 知道已完成與進行中事項
- [ ] 知道主要歷程與重大變更
- [ ] 知道文件閱讀順序
- [ ] 知道哪些資料可能已過期
- [ ] 知道目前卡點
- [ ] 知道下一步及負責人
- [ ] 知道仍需向誰確認哪些事項

若仍有缺口，持續標示「待確認」，不得宣稱已完全掌握專案。
